Corrections

If a sheet shows something the Board's record does not — a wrong date, a missing entry, a caption that is not the Board's — we want to know, and we would rather be told than be quietly distrusted.

How to report one

Report a correction on GitHub

The form asks for the docket, the entry, what is wrong, and where the right answer is (usually the Board's own file, which every entry links). Reports are public, and so is what was done about them: that is the correction log.

What happens next

  • Within two business days a person replies on the report — fixed, needs more, or disagreed, with the reason.
  • A fix propagates. Every entry carries its source, so a correction changes the record once and every page showing that entry follows; nothing is patched by hand on one page.
  • The Board's record wins. Where the disagreement is about what the Board printed, the Board's file settles it. Where it is about how {{ site_name }} labelled or folded an entry, the answer is a change to the published method, not a one-off edit.
  • Corrections survive. A hand correction is recorded as its own event with its own provenance, so a later re-run of the pipeline cannot silently overwrite it.

What this page does not promise

That every entry is caught. The Board's search fails in ways that look like success; the coverage page says what is watched and records every gap the monitor has found.
