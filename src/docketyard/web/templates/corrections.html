Corrections

A correction here is a correction of this record — what {{ site_name }} shows — against what the Board's record shows. {{ site_name }} does not correct, annotate, or speak for the Board's record. If a filing or decision itself is wrong, that is a matter for the Board and the parties; if this site shows the Board's record wrongly, that is ours to fix, and we would rather be told than be quietly distrusted.

What counts as a correction

  • A sheet shows a date, caption, filer, type or summary that differs from what the Board's own file or record search shows.
  • An entry the Board has posted is missing from its sheet, or appears on the wrong docket.
  • A label or fold this site derives (see methodology) is misleading for an entry.

Not a correction: disagreement with what the Board printed, or with what a filing says. The Board's record is the record, and every entry links to it.

Not under this promise either: a misreading in the machine-read text of a document (the text pages, labelled as machine-read with the engine and version that read them). Reports of those are welcome through the same form and a person reads them, but the seven-day expectation below is for the record — the sheet, the entry, the file — not for what a machine read from inside a file. The scan beside every text page is the record.

How to report one

Report a correction on GitHub

The form asks for the docket, the entry, what is wrong, and where the right answer is — usually the Board's own file. Reports are public, and so is what was done about them: that is the correction log.

What happens next

  • A person reads every report. Corrections are usually made within seven days; that is how it has gone, not a guarantee. The report shows its own status — fixed, needs more, or disagreed with the reason — so you never have to wonder.
  • A fix propagates. Every entry carries its source, so a correction changes the record once and every page showing that entry follows; nothing is patched by hand on one page.
  • The Board's file settles it. Where the disagreement is about what the Board printed, the Board's own file decides. Where it is about how {{ site_name }} labelled or folded an entry, the answer is a change to the published method, not a one-off edit.
  • Corrections survive. A hand correction is recorded as its own event with its own provenance, so a later re-run of the pipeline cannot silently overwrite it.

What this page does not promise

That every entry is caught, or a fixed turnaround. The Board's search fails in ways that look like success; the coverage page says what is watched and records every gap the monitor has found.
